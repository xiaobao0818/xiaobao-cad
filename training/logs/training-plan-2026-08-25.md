### 1.3 根因分析（本轮诊断结论）
threeview2d 与 pumpboth-bare 是**同一根因的两个表现：首绘完整性缺失**。
- 任务提示词（tasks.mjs）**已明确**要求三视图+区域坐标、2D 图纸要素——不是提示缺失，是**执行纪律**问题
- 带 review 时自我纠正到 100（reviewRounds 6/6/2），EVAL 无 review 即暴露 → 首绘只完成"主要交付物"（主视图 / 3D 模型），遗漏其余交付物（俯/侧视图 / 尺寸标注+图框+标题栏），等第二轮的追问——但 EVAL 没有追问
- 现行【首轮纪律】(js/ai.js L53) 只约束"必须调工具"，**未约束"一次覆盖全部交付物"**；draw_entities schema 描述也只说"一次可创建多个"，未强调"多视图/多要素一次画完"

## 二、提升方案（阶段5 变量2 起）

### 2.0 红线（沿用，全部保留）
1. 一次只改一个变量；固定 EVAL 集对照；失败轮必须计入；noproduce 计数；timeout 剔除但报数
2. modeInferred 不当事实（本轮结论全部基于硬证据轮）
3. 预算分散：pumpduty3d-bare 仅做指标3留出测量（封顶 5 轮），不再做其它训练
4. 不改 tasks.mjs 任务提示词、不改 acceptance.mjs（不在允许改动列表）
5. 每变量：npm test 绿 + 提交信息含数字与不成立结论 + 固定集回退 >5 分即回退该变量

### 2.1 变量2：首绘完整性纪律（唯一改动点：js/ai.js）
- **a. SYSTEM_PROMPT【首轮纪律】追加**（通用原则，不写坐标）：
  "任务包含多个交付物时（如三视图=主视图+俯视图+侧视图；商用图纸=视图+尺寸标注+图框+标题栏；装配体=多个零件），**第一轮工具调用必须一次性创建全部交付物**，不允许首轮只完成一部分等待追问。"
- **b. draw_entities 工具描述追加**：
  "多视图/多要素图纸请在同一次调用中画完所有视图与要素（视图、尺寸标注、图框、标题栏等）。"
- **固定 EVAL 集（12 轮 ≈ 30min）**：threeview2d×3 + pumpboth-bare×3 + axialflow3d×2 + doublesuction3d×2 + shaft3d×2
- **基线（现库即基线，不必预跑）**：68 / 67 / 89 / 88 / 88(近3轮)
- **成功标准**：threeview2d 中位≥90 且 3/3 全有效；pumpboth-bare 中位≥85；其余三任务不回退；0 noproduce

### 2.2 变量3（视变量2结果）：图纸要素知识注入
- 若变量2后 pumpboth-bare 仍缺"尺寸标注/图框/标题栏" → knowledge/data.js 增加"商用图纸要素检查清单"条目（主视图同心圆+直径标注+图框+标题栏+明细栏），供 query_knowledge 首轮检索
- 固定 EVAL 集同 2.1（12 轮）

### 2.3 变量4（视结果）：3D 布尔完整性
- 若 axialflow3d/doublesuction3d 布尔数量仍差 1 → 系统提示 3D 规范强化"装配体必须完成全部布尔运算（差集/融合）后再收尾，验收按布尔次数计"
- 固定 EVAL 集（10 轮）：axialflow3d×3 + doublesuction3d×3 + casing3d×2 + minipump3d×2

### 2.4 指标3 留出工况扩充（预算封顶 5 轮 ≈ 12min）
- 5 个未用工况（40/60/2900、60/45/2900、150/25/2900、80/20/2900、250/18/1450）× 1 轮，HOLDOUT=1 抽（用过即弃）
- 目的：指标3 独立工况 3 → 8 组；同时检验变量2/3 的提示改动未损害换工况泛化
- 时机：变量2/3 完成后跑

### 2.5 测量层增强（不改模型行为，只改展示口径）
- northstar/stats 增加"硬证据轮"（modeInferred=false）拆分：指标2 窗口同时给"含推断/仅硬证据"两口径
- 目的：让"提升"结论建立在硬证据上；不剔除任何轮，只分层展示

### 2.6 指标2 单调性
- 不专门改动；靠高质量轮次自然滚出历史低点；每个提交如实报告 ⚠️ 状态
