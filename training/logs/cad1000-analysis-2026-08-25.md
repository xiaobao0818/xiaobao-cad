## 1. 数据集构成

- **1,021.64 小时**真实操作录屏，**597 个工作流**，10 款软件：
  AutoCAD 238 流程/502h（49%）、SOLIDWORKS 149/209h、SketchUp 49/143h、CATIA 45/54h、
  Revit 建筑/结构、Siemens NX、STAAD.Pro、V-Ray、D5 Render
- 总量 256.6 GiB，8,973 个文件
- 每个工作流自包含（`<软件>/<workflow-id>/`）：
  `clip.mp4`（30fps 录屏）、`events.json`（鼠标键盘事件）、`frame_events.json`、
  `narration.json`（逐帧讲解）、`task_desc.json`（任务规格）、`rubrics.json`（评分标准）、
  `task_overview.pdf`（人类任务书）、`input_files/`（素材）、`output_files/`（成品文件）

## 2. 制作方法论（其"训练内容"的核心）

每个工作流 = **完整的可复现工程作业**：
1. 人类工程师实际完成一项 CAD 任务，全程录屏 + 采集鼠标键盘事件
2. 逐帧标注 narration：`{start_s, end_s, action, intent, app, details}` —— 动作 + 意图两层描述
3. 任务规格 task_desc 结构化：`task`（一句话）+ `description`（构成描述）+ `dimensions[]`（
   `{id, element, measurement}` 尺寸表）+ `deliverables[]`
4. rubrics：自然语言验收清单 R1~Rn（几何构成 + 标注/表现要求）
5. 成品文件可被机器检验（"produce a file that can be inspected for dimensions, structure and completeness"）

## 3. 内容样本解剖（实测）

### 3.1 机械类工作流（与本项目最相关）
`autocad/01dd0e82…` → "Create a dimensioned 2D technical drawing of a mechanical support stand"
- task_desc 含 **D1~D15 结构化尺寸表**：立柱外宽 45mm / 内宽 35mm / 撑高 50mm / 顶板厚 15mm /
  斜臂角 0.7854 rad / 斜臂长 120mm / 端部半径 15.9mm / 安装耳外径 30mm / 孔径 15mm 等
- rubrics R1~R6：中心立柱 / 顶板 / 对角撑 / 圆头安装耳带孔 / 斜臂圆孔眼 / **尺寸标注必查**（R6）

### 3.2 真实成品 DWG 解析验证（用我们自己的解析器）
下载 `output_files/DWG2.dwg`（50KB）解析：
- 实体构成：**20 线 + 13 DIMENSION + 3 圆 + 3 弧**（26 个可映射实体 + 13 个标注）
- **标注数值与 task_desc 尺寸表逐项吻合**：45.0=D1、35.0=D2、50.0=D3、15.0=D4、
  0.8 rad=D5、120.0=D6、15.9=D7、30.0=D8 —— 成品与规格一致，数据质量可信
- 图层纪律：真人绘制也只用 0 层 + Defpoints（说明图层规范不是图纸完成度的关键）

### 3.3 建筑类工作流（住宅平面图）
- task_desc：分区式布局描述（中央起居 + 四卧 + 厨卫 + 停车位…）
- rubrics R1~R10：按**区域**检查（后侧三房 / 上部卧室+餐厅 / 中央起居 / 交通流线 / 门窗开启 /
  房间标签 + 家具 / **视觉差异化表现** R10）
- narration 337 段：`intent`（如 "Configure drawing measurement units"）+ `action`（如
  "typed the command abbreviation un … and pressed Enter"）—— 意图-动作双层，与我们的
  工具调用"先想清楚为什么调用"理念一致

## 4. 与小宝CAD 训练体系的对照

| 维度 | CAD 1000 Hours | 小宝CAD | 结论 |
|---|---|---|---|
| 任务规格 | 结构化：task+description+**dimensions[]**+deliverables | tasks.mjs 提示词内嵌尺寸散文 | **他们的结构更防幻觉**，可借鉴 |
| 验收 | 自然语言 rubrics R1~Rn（完整性导向） | 程序化 checks（countInBand/kindCount/尺寸值/图框…） | 我们更精确；方向一致 |
| 过程监督 | narration 动作+意图 | 首轮纪律/工具轨迹 | 佐证我们的"首绘完整性"变量 |
| 成品可检验 | DWG 可解析验证 | DXF/DWG 导出 + AI 审阅 | 我们已具备 |
| 训练方式 | computer-use（GUI 代理） | API 函数调用（MiniMax M3） | 不可直接迁移权重，只能学内容/结构 |

## 5. 已落地学习（本次提交）

**DIMENSION 实体解析补全（js/dwg.js + 测试）**
- 发现：真实 AutoCAD 图纸的标注以 **DIMENSION 实体**存储，而我们的解析器此前
  "暂不支持"（静默丢弃）→ 导入真实图纸时标注全丢
- 实现：`dimensionType` 低 4 位（与 DXF flag 70 编码一致）映射
  linear（x1..y3+angle）/ angular（cx,cy+a1,a2+r+tx,ty）/ diametric / radial（px,py），
  附带 `measurement → value`、`text`
- 验证：CAD1000 成品图纸 13 个标注全部读出且数值与规格表吻合；
  npm test 全绿（含示例图纸 9 个 DIMENSION 断言 + 合成数据单元测试）

## 6. 候选学习清单（按优先级，需走阶段5变量协议或另行批准）

1. **P0 图纸规范知识注入（变量5候选）**：knowledge/data.js 增加"商用图纸要素"条目
   —— 从真实机械图纸提炼：技术图纸 = 几何构成（简单）+ 完整标注（线性/直径/半径）+ 图框标题栏；
   标注样式 ISO-25、单位 mm、⌀/R 前缀。经固定 EVAL 集测量后决定去留
2. **P1 任务规格结构化重构（tasks.mjs，不在允许改动列表，需用户批准）**：
   引入 `dimensions[]` 数组模式（元素+数值），提示词引用而非内嵌散文，降低数字幻觉
3. **P1 数据集派生评测任务**：按机械类 task_desc（支撑架/活塞等）新增评测任务，
   验收镜像其 rubrics（几何构成 + 标注数量/数值）—— 扩大 24 任务之外的回归面
4. **P2 物理验证式偏好数据（受 tryforge/cad-1000-dpo 启发）**：用我们的 OCC 内核
   （体积/配合间隙/布尔次数）自动生成"好/坏"成对样例 → 可作未来 SFT/评测材料；
   当前 API 模型无法微调，仅作评估增强
5. **P2 过程意图纪律（并入变量2）**：narration 的"intent 先行"结构佐证
   首绘完整性纪律（多交付物一次画完），外部证据，无需单独变量

## 7. 局限与风险

- 主数据集未声明明确 license（cardData 无 license 字段；衍生 tryforge 版为 cc-by-sa-4.0）：
  **仅用于学习分析，不将其中文件分发/入库**（本次只临时下载 1 个 50KB DWG 做解析验证）
- 256GB 视频对 API 模型无直接用途（不能微调 MiniMax M3）；可用的是文本规格/结构/规范
- 数据集面向 GUI 代理（屏幕+鼠标），与我们的函数调用范式不同 —— 学"做什么/验收什么"，
  不学"怎么点鼠标"

成品可机器检验 —— 与我们方向一致且可互相印证。本次已落地最有价值的一项（DIMENSION 解析），
其余按 P0~P2 排队，经阶段5变量协议逐项验证。
