# 系统性学习方案：从外部 CAD 数据集持续学习（2026-08-25）

## 0. 目标与适用范围

把 CAD 1000 Hours（及未来同类外部数据集）作为**外部训练素材库**，建立一条可重复的
**学习管线**：`盘点 → 批量挖掘 → 提炼 → 注入 → 测量 → 验证 → 归档`，每次学习都留下
可审计的证据链（样本量、统计、前后指标、不成立结论）。适用对象：训练内容（提示/知识/规格）、
解析能力、评测面、方法论。

约束前提（沿用全部红线）：
- 一次只改一个变量；固定 EVAL 集对照；失败轮计入；modeInferred 不当事实
- 允许改动点：js/ai.js 系统提示与工具 schema、knowledge/data.js、training/pumpdesign.mjs、training/specs.mjs
- tasks.mjs / acceptance.mjs 改动需另行批准
- 主数据集无明确 license：只读分析，素材文件不入库、不分发
- 预算分散：pumpduty3d-bare 只做指标3留出测量（封顶 5 轮）


### G0 探针门禁（制度化，2026-08-25 审计后新增）

**任何 knowledge/data.js 或 js/ai.js 系统提示的知识性改动，在跑正式固定 EVAL 集之前，
必须先通过探针门禁**：`bash tests/probe-regression.sh`（flange2d/volute2d/threeview2d 各 1 轮 EVAL，
阈值默认 85，`THRESHOLD=` 可调）。三任务代表"无图框零件图/曲线型线/多视图"三类易被全局规则污染的场景。

背景：变量5 幅面条目因缺此门禁污染 flange2d(100→50)/volute2d(100→17)，多耗 24 轮预算。

## 1. 学习管线总览

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ P0 盘点  │ → │ P1 挖掘  │ → │ P2 提炼  │ → │ P3 注入  │ → │ P4 测量  │ → │ P5 归档  │
│ 素材+许可 │   │ 批量统计 │   │ 证据蒸馏 │   │ 变量化改造│   │ 固定集对照│   │ 报告+复盘│
└─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
                    ↑                                        │
                    └────────── 发现新缺口 → 能力补全分支 ────┘
```

每轮学习产出：`学习报告（样本量+统计+证据）+ 变量提交（数字+不成立结论）+ 归档文件`。

## 2. 各阶段细则

### P0 盘点（一次性，可复用）
- 建立"素材→能力"映射表，明确每个素材子集学什么：
  | 素材子集 | 学习目标 | 产出 |
  |---|---|---|
  | AutoCAD 机械类工作流（238 流程中抽样） | 2D 技术图纸规范（构成/标注/图层） | 知识条目 |
  | AutoCAD 建筑类工作流 | 多区域布局完整性、图纸要素清单 | 验收思想、知识条目 |
  | SOLIDWORKS/CATIA/NX 工作流 | 3D 零件-装配建模步骤顺序 | 提示纪律（3D 步骤序） |
  | rubrics.json 全集 | 验收粒度与完整性导向 | acceptance 模式对照 |
  | task_desc.json 全集 | 任务规格结构化模式 | tasks.mjs 重构提案 |
  | narration.json | 意图-动作双层执行纪律 | 首绘完整性纪律佐证 |
  | 成品 DWG 批量 | 解析器能力缺口清单 | parser 功能提交 |
  | tryforge/cad-1000-dpo | 物理验证式偏好数据思想 | 评测增强提案 |
- 许可确认：只读分析合法；任何入库/分发的素材必须有明确许可，否则剔除

### P1 批量挖掘（每批 1~2 小时，可重复）
- 机械类抽样 **N=20~30 个工作流**（优先任务名含 dimensioned/technical/part/drawing 者）
- 批量下载 task_desc + rubrics + 成品 DWG（跳过 >5MB 的），用**我们自己的解析器**全部解析
- 统计输出（机器生成，存 training/logs/cad1000-mining-<date>.json/md）：
  1. 实体构成分布：典型机械图纸 = ?线 + ?圆/弧 + ?标注 + ?文字（均值/中位数/范围）
  2. 标注规范：linear/diametric/radial 占比、数值小数位、ISO-25 样式使用率、⌀/R 出现率
  3. 规格吻合率：标注测量值与 task_desc.dimensions[] 的吻合比例（数据质量审计）
  4. 图层使用：真实图纸的图层纪律实况
  5. 解析器缺口：批量解析中失败/丢失的实体类型清单（→ 能力补全分支）
- 产出：mining-report + 素材清单（工作流 id、样本截图位点）

### P2 提炼（证据蒸馏）
- 每条候选知识必须带**证据**：来自哪个统计、样本量 N、出现率 p
- 输出三类产物：
  a. **知识条目候选**（knowledge/data.js）：商用图纸规范（构成参考、标注规范、要素清单）
  b. **提示规则候选**（js/ai.js）：首绘完整性纪律（多交付物一次画完）、3D 步骤序
  c. **规格条目候选**（specs.mjs）：图纸标注规范（ISO-25、⌀/R、单位 mm、小数位规则）
- 每条标注：`[证据: N=23, p=87%]`，证据不足（N<10 或 p<60%）的条目标记"待证"不入库

### P3 注入（变量化，一次一个）
| 变量 | 内容 | 来源证据 | 固定 EVAL 集 |
|---|---|---|---|
| 变量2 | 首绘完整性纪律（系统提示+draw_entities 描述） | narration intent 先行 + threeview2d/pumpboth-bare 诊断 | threeview2d×3 + pumpboth-bare×3 + axialflow3d×2 + doublesuction3d×2 + shaft3d×2 = 12 轮 |
| 变量5 | 图纸规范知识条目（knowledge/data.js） | P1 批量统计（标注构成/ISO-25/⌀R） | 同上 12 轮 + 图纸类任务 2D 集 |
| 变量6 | 3D 步骤序纪律（视变量2结果） | SOLIDWORKS 工作流步骤序 + axialflow3d/doublesuction3d 布尔差1 | axialflow3d×3 + doublesuction3d×3 + casing3d×2 + minipump3d×2 = 10 轮 |

- 成功标准：目标任务中位 ≥90 且全有效；同集其余任务不回退（>5 分回退该变量）；0 noproduce
- 防过拟合：只写通用原则，不写任务坐标/区域数字；统计数字（如"典型 20 线+13 标注"）
  作为参考范围注入，不写死验收阈值

### P4 测量与泛化回归
- 每变量：固定 EVAL 集前后对照（现库即基线）+ npm test 全绿
- 每 2 个变量后：24 任务 ×1 轮全面回归（≈1h）防过拟合
- 指标3 留出工况扩充：5 个未用工况 ×1 轮（封顶），验证提示/知识改动未损害换工况泛化
- 测量层：northstar/stats 增加"硬证据轮"（modeInferred=false）口径拆分

### P5 能力补全分支（独立于训练变量，随时触发）
- 批量解析发现的新缺口（如 HATCH 边界、SPLINE 拟合、INSERT 块属性）→
  每项 = 解析器功能提交（js/dwg.js + 测试 + npm test 绿），不占训练变量
- 已落地示例：DIMENSION 实体解析（commit 63cb2d3）
- 能力补全反向收益：导入真实图纸 → AI 可见完整图纸内容 → 训练/评测素材更真实

### P6 评测面扩展（需用户批准，tasks.mjs 不在允许列表）
- 新增 2~3 个数据集派生评测任务（如"支撑架 2D 技术图纸"），任务规格镜像其
  task_desc 结构化尺寸表，验收镜像 rubrics（几何构成 + 标注数量/数值）
- tasks.mjs 重构提案：引入 `dimensions[]` 数组模式（元素+数值），提示词引用而非散文内嵌
- 派生任务只作回归评测面，不进北极星指标（防指标膨胀/泄漏）

## 3. 学习闭环的重复机制

- 每轮学习（P1→P4）为一次"学习迭代"，迭代间可换素材源（CAD1000 → sample-100-hours →
  Computer Use Large → 自采数据）
- **饱和判据**（何时停止该素材源）：连续 2 批挖掘新条目率 <10%，或统计分布收敛
  （新增样本不再改变均值 >1%）
- 每迭代末归档：mining-report + 变量提交 + 学习复盘（数据集贡献归因：诚实区分
  "数据集学到的"与"其他变量带来的"）

## 4. 预算与时间线（第一阶段，可执行版）

| 步骤 | 内容 | 预算 | 耗时 |
|---|---|---|---|
| P0 盘点 | 映射表 + 许可确认 | 0 | 已基本完成（分析文档） |
| P1-1 挖掘 | 机械类 N=20 抽样 + 批量解析统计 | 0（纯本地） | ~1h |
| P2-1 提炼 | 图纸规范知识条目候选（带证据） | 0 | ~30min |
| P3-1 变量2 | 首绘完整性纪律 | 12 轮 EVAL | ~30min |
| P3-2 变量5 | 图纸规范知识注入 | 12 轮 EVAL | ~30min |
| P4-1 | 指标3 留出扩充 + 全面回归（视需要） | 5~29 轮 | ~15~70min |
| P5-1 | 批量解析缺口补全（按发现） | 0 | 每项 ~30min |
| 小计 | — | **~30~55 轮** | **~3~4h** |

P6（评测面扩展）单列，批准后另计（新增任务定义 + 回归 ≈ 1h）。

## 5. 完成标准与门禁

- 每变量：固定集达标 + npm test 绿 + 提交含数字与不成立结论
- 阶段完成：四弱任务（threeview2d/pumpboth-bare/shaft3d/axialflow3d）固定集中位 ≥90；
  指标2 末窗硬证据且单调；指标3 ≥6 组独立留出工况
- 能力面：批量解析缺口清单清零（或逐项标记"低价值不做"）
- 全流程零"剔除失败轮"行为

## 6. 风险清单

- 数据集许可证未明 → 全部只读，入库前逐一确认
- 过拟合固定 EVAL 集 → 统计值只作参考范围 + 全面回归
- 把数据集贡献误记为其他变量功劳 → 每迭代独立归因
- MiniMax-M3 版本漂移 → 每提交记录模型版本
- 批量挖掘消耗时间而非 API（纯本地，可控）；EVAL 预算按表封顶

## 7. 第一阶段执行入口

建议顺序：**P1-1 挖掘（本地，不花 API）→ P2-1 提炼 → P3-1 变量2（首绘完整性）→
P3-2 变量5（知识注入）→ P4-1（留出扩充+回归）→ 归档**。
P5 能力补全按挖掘中发现的缺口随时穿插；P6 需批准后另排。
