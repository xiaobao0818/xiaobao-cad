# 几何度量自检 A/B 实验报告（2026-10-21）

## 一、假设与实现

**假设**：把模型当前的几何度量（体积/面数/壁厚估计/包围盒）自动反馈给 AI，
能让它在首轮内发现"漏件/过薄/退化/冗余"，从而提高首绘成品率。

**实现**（已提交代码，默认关闭）：
| 层 | 改动 |
|---|---|
| `js/three-dim/occ-kernel.js` | 新增 `bodyMetrics(id)`：体积（GProp）、表面积（SurfaceProperties）、面数（TopExp_Explorer）、棱出现次数、包围盒 |
| `js/three-dim/app3d.js` | 新增 `geometryReport()`：聚合可见实体（数量/类型分布/总体积/包围盒/各实体体积·面数·有效厚度 2V/A），输出警告（<0.8mm 过薄、<1mm³ 退化、>25 实体冗余） |
| `js/ai.js` | 每轮工具执行后把报告追加到最后一个 tool 结果（不新增消息角色，避免兼容接口拒绝中途 system 消息）；系统提示增加一条自检说明；新增 `geoSelfCheck` 开关（**默认 false**） |
| `tests/kernel.test.mjs` | bodyMetrics 单测（体积/表面积/6 面/棱出现次数 24/包围盒） |

## 二、实测结果（doublesuction3d，各 3 轮）

| 条件 | 各轮首绘分 | 中位 | 单轮耗时（约） |
|---|---|---|---|
| OFF（无自检） | 100 / 88 / 79 | **88** | 4 分钟 |
| ON（开启自检） | 88 / 88 / 0（无产出） | **88** | **20 分钟** |

**Δ中位 = 0；Δ耗时 ≈ +400%；ON 出现 1 轮 noproduce。**

## 三、机制验证（功能确实生效）

ON 轮次助手最终回复中出现「**自检核对**」段落，原文引用：
> 总体积 ≈7.09M mm³，包围盒 180×180×130mm，与设计尺寸一致
> 所有实体有效厚度 ≥2.2mm，无过薄/零体积异常
> 叶片 6mm 厚（3~6mm 合格）、轮盘 8mm（≥8mm 合格）

→ 模型**读到并使用了**注入的度量数据（体积/包围盒/厚度均来自我们的报告），
但**得分未变**：该任务的扣分点是"布尔数量不足（4 < 5）"，不是几何度量能覆盖的语义错误。

## 四、结论

1. **未验证到成品率提升**（单任务 A/B，中位持平；ON 还多了一轮无产出）。
2. **代价显著**：ON 单轮耗时约 20 分钟（OFF 约 4 分钟），上下文 token 增加。
3. **默认关闭**：`geoSelfCheck: false`。保留开关与内核 `bodyMetrics` API，
   供后续实验（例如只注入一次、或做成按需工具）。

## 五、未完成与局限（如实记录）

- `pumpboth-bare` 的 ON 组未跑完（预估 45~60 分钟/3 轮，时间成本过高，主动中止）——
  该任务的 ON/OFF 对比**没有数据**。
- 单任务、n=3，方差大（OFF 组本身 79~100）；结论只对 `doublesuction3d` 成立。
- 报告里的"有效厚度 2V/A"是特征尺寸估计，不是真实壁厚（异形件会偏差）。

## 六、若未来重启此方向的建议

1. **按需工具**：`check_geometry()` 由模型自行调用，而非每轮自动注入（成本可控）；
2. **只注入一次**：首轮工具批结束后注入一次摘要，避免多轮回吐；
3. **改走验收侧**：把度量用于自动修复/评分提示，而不是塞进对话上下文。
